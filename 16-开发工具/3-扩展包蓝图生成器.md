# 扩展包蓝图生成器（admin:ext-make-pro）

`admin:ext-make-pro` 是扩展包开发的入口命令。它不仅生成最小可运行的扩展包骨架，还能**从已有数据表反推** Model / Migration / Seeder，并自动产出**开发蓝图文档**（让 AI 或协作者拿到骨架就知道下一步做什么）。

> 阅读本文前，建议先了解扩展包基本机制，见 [开发扩展](../9-开发扩展/2-开发扩展.md)。

## 它解决什么问题

过去生成扩展包骨架后，开发者会立刻遇到一连串坑：

- `updates/` 是空目录，建表 migration 要从零写；
- 写了 migration 但**没登记进 `version.php` 就不会执行**（这是最常见的"迁移不生效"原因）；
- 没有开发计划、没有字段说明、没有接口交付文档，AI 接手时不知从何下手；
- 多个扩展包的表名互相撞名，无法区分某张表属于哪个扩展。

`admin:ext-make-pro` 把这些问题前置解决：建包即建表、即登记、即出文档、即定表名前缀。

## 命令总览

```bash
php artisan admin:ext-make-pro <vendor>/<name> [选项]
```

| 选项 | 说明 |
|------|------|
| `--models=` | 逗号分隔的表名。表已存在则**反推**生成 Model + Migration；表不存在则生成**占位**骨架（之后补字段） |
| `--seed` | 为每个 `--models` 表生成**幂等** Seeder（带 mock 数据），自动登记进 `version.php` |
| `--blueprint` | 生成 `docs/` 蓝图文档（指定 `--models` 时默认开启） |
| `--marketplace` | 生成应用市场介绍与落地页 |
| `--api` | 扩展包带移动端接口（生成 member-api / admin-api 相关骨架目录与文档） |
| `--db-connection=` | 反推用的库连接（默认 `database.default`） |
| `--table-prefix=` | 新建表的表名前缀；默认从包名自动缩写，传空串禁用前缀 |

## 三种典型用法

```bash
# 1. 新系统，表还不存在 —— 只建骨架 + 占位表 + 蓝图
php artisan admin:ext-make-pro acme/cms \
  --models=articles,categories \
  --seed --blueprint

# 2. 表已存在于库中 —— 反推 Model + Migration + Seeder
php artisan admin:ext-make-pro acme/cms \
  --models=articles,categories \
  --seed --blueprint \
  --db-connection=mysql

# 3. 完整形态：带接口 + 准备发布市场
php artisan admin:ext-make-pro acme/cms \
  --models=articles,categories \
  --seed --api --marketplace
```

## 反推模式 vs 占位模式

`--models` 给的每一张表，命令会先查库判断是否存在：

| 情况 | 行为 |
|------|------|
| 表**已存在** | 读取真实字段、类型、注释、主键、索引，反推生成 Model + Migration + Seeder，Migration 文件头标注「反推自现有表」 |
| 表**不存在** | 生成占位 Migration（只有 `id` / `name` / 时间戳，顶部留 `// TODO` 注释），并在 `schema.md` 标记为待建表，提示阶段 1 补字段 |

> 反推是"读结构写代码"，不会改动现有数据库。占位模式产出的 Migration 需要你在阶段 1 补全真实字段后再执行。

## 自动登记 version.php

这是本命令的核心价值。扩展包的迁移/seeder **必须登记进 `version.php` 才会执行**（机制见 [开发扩展](../9-开发扩展/2-开发扩展.md)）。命令每生成一个 migration 或 seeder，就自动追加到 `version.php`：

```php
return [
    '1.0.0' => [
        'Initialize extension.',
        'create_articles_table.php',
        'create_categories_table.php',
        'seed_articles_data.php',
        'seed_categories_data.php',
    ],
];
```

顺序固定：先所有 `create_*`，后所有 `seed_*`。生成后直接执行即可生效：

```bash
php artisan admin:ext-update acme.cms
```

## 表名前缀约定（多扩展共存）

为了避免不同扩展包的表互相撞名、并能在数据库里一眼识别表的归属，扩展包的**新建表**统一加前缀。

### 前缀如何生成

- **默认从包名自动缩写**：取包名 name 段 → snake_case → 去掉 `_manager`/`_system`/`_plugin`/`_extension`/`_chart`/`_charts`/`_module` 后缀 → 若仍超过 14 字符取首段 → 末尾加 `_`。

| 包名 | 自动前缀 |
|------|----------|
| `acme/miniapp_manager` | `miniapp_` |
| `acme/competition_management` | `competition_` |
| `acme/blog` | `blog_` |

- **手动覆盖**：`--table-prefix=myprefix_`。
- **禁用前缀**：`--table-prefix=`（传空串）。

### 物理表名 vs Model 类名

前缀只影响**物理表名**，Model 类名用**逻辑名**（不带前缀）：

| | 物理表名 | Model 类名 |
|---|----------|------------|
| 例 | `miniapp_configs` | `MiniappConfig` |

- 物理表名贯穿 migration 的 `Schema::create`、Model 的 `$table`、seeder 的 `DB::table`。
- Model 类名、Resource 类名等用逻辑名。

> **只对新建表（占位模式）加前缀，反推的已存在表保持原名**——避免改动现有库结构。

### 文档落点

生成产物中，表名前缀约定写在以下位置：

- `docs/database/schema.md` ——「表名前缀约定」章节，列出前缀值与规则。
- `docs/tasks/PLAN.md` ——阶段 1 提示当前前缀，并带自检项「确认新建表名都带前缀」。

## 生成的 Seeder 特点

`--seed` 生成的 Seeder 是**幂等**的：

```php
// 跑第二次会自动跳过，不会重复写入
if (DB::table('articles')->count() > 0) {
    return;
}
```

mock 数据按字段语义生成：金额字段填随机金额、布尔字段填 0/1、`avatar` 填占位图、`email`/`mobile` 按格式生成、时间字段填当前时间。

## 蓝图文档（--blueprint）

`--blueprint` 会在扩展包 `docs/` 下生成一整套开发文档，让 AI 或协作者按图施工：

| 文档 | 作用 |
|------|------|
| `docs/BLUEPRINT.md` | 总纲：定位、功能模块清单、技术架构、开发阶段指引 |
| `docs/database/schema.md` | 字段表：每张表的字段、类型、注释、推荐控件、表名前缀约定 |
| `docs/tasks/PLAN.md` | 可勾选看板：阶段 0~5 任务清单 + 交付检查清单，是"做到哪了"的唯一事实来源 |
| `docs/delivery/api_delivery.md` | 接口交付文档（`--api` 时）：移动端开发的唯一数据源 |
| `docs/MARKETPLACE.md` | 应用市场介绍（`--marketplace`）：卖点、场景、功能清单、配图提示词 |
| `resources/views/landing.blade.php` | 落地页（`--marketplace`） |

`README.md` 也会被重写为开发指南（目录结构、开发工作流、常用命令）。

## 与代码生成器的分工

| 命令 | 何时用 | 产出 |
|------|--------|------|
| `admin:ext-make-pro` | **开包时用一次** | 骨架 + 数据层（Model/Migration/Seeder）+ 文档蓝图 |
| `admin:scaffold --extension=` | **写业务代码时反复用** | 后台 Controller、API 控制器、Resource（见下一篇） |

即：`ext-make-pro` 负责"建包 + 建表 + 出蓝图"，`scaffold` 负责"写 CRUD 和接口代码"。

## 迁移硬约束（务必遵守）

无论用命令生成还是手写，扩展包的迁移/seeder 必须满足 3 个约束（源于 `DatabaseUpdater`）：

1. **具名类、无 namespace**：不能用匿名类，文件里不能有 `namespace` 声明。
2. **无时间戳前缀**：文件名 `create_<table>_table.php` / `seed_<table>_data.php`，**不是** Laravel 的 `2024_01_01_000000_create_xxx.php`。
3. **必须登记 `version.php`**：未登记的脚本不会执行。

执行入口是 `php artisan admin:ext-update <vendor>.<name>`，**不是** `php artisan migrate`。
