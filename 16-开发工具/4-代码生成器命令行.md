# 代码生成器命令行（admin:scaffold）

`admin:scaffold` 是命令行代码生成器，从数据库表结构读取字段信息，批量生成后台 CRUD 代码。它和 [智能脚手架](2-智能脚手架.md)（可视化界面版）识别字段语义的逻辑一致，但更适合**批量生成**和**脚本化开发**。

> 完整选项与生成规则见项目内 `vendor/dcat-plus/laravel-admin/docs/scaffold-command.md`。本文聚焦接口生成与扩展包模式能力。

## 它能生成什么

除了基础的 Model / Controller / Lang / 路由 / 权限 / 菜单，现在还支持：

- **member-api 控制器**（C 端接口）+ JsonResource
- **admin-api 控制器**（管理端接口）+ JsonResource
- **JsonResource** 类（每个 model 一个）
- 以上代码可生成到**主项目**，也可生成到**扩展包**

## 新增选项

| 选项 | 说明 |
|------|------|
| `--api` | 生成 member-api 控制器 + Resource，路由写入 `app/Api/routes.php` |
| `--admin-api` | 生成 admin-api 控制器 + Resource，路由写入 `app/Admin/Api/routes.php` |
| `--resource` | 每个 model 生成一个 JsonResource 类（`--api`/`--admin-api` 已隐含包含） |
| `--extension=` | 代码生成到指定扩展包（`vendor/name`），命名空间/目录/路由按扩展包约定 |

原有选项（`--connection`、`--table`、`--controller-namespace`、`--model-namespace`、`--force`、`--menu-parent`、`--menu-icon`、`--role`）保持不变。

## 主项目用法：一次生成后台 + 双端 API

```bash
php artisan admin:scaffold \
  --table=orders \
  --api --admin-api --resource
```

生成产物（表 `orders`）：

```text
app/Models/Order.php
app/Admin/Controllers/OrderController.php          # 后台 CRUD（继承 AdminController）
app/Http/Resources/OrderResource.php               # JsonResource
app/Api/Controllers/OrderController.php            # member-api（继承 App\Api\Controllers\BaseApiController）
app/Admin/Api/Controllers/OrderController.php      # admin-api（继承 App\Admin\Api\Controllers\BaseApiController）
lang/zh_CN/order.php
```

路由自动写入三个文件：

```text
app/Admin/routes.php        → $router->resource('order', OrderController::class)
app/Api/routes.php          → $router->apiResource('/order', ...) + 批量/导入导出辅助端点
app/Admin/Api/routes.php    → $router->apiResource('/order', ...) + 批量/导入导出辅助端点
```

### 生成的 API 控制器特点

- **member-api**：继承 `App\Api\Controllers\BaseApiController`，自带列表/详情/增/删/批量更新/批量删除。
- **admin-api**：继承 `App\Admin\Api\Controllers\BaseApiController`，除上述外还含导入模板下载/导入/导出/字段元数据接口。
- 两个基类都有抽象方法 `getValidationRules(string $action): array`，生成后**默认是空实现**，必须按业务补全。

### 生成的 Resource 特点

`toArray()` 会按表字段自动填好注释，供 Scramble 生成接口文档：

```php
public function toArray($request)
{
    return [
        /**
         * 订单ID
         * @var int
         */
        'id' => $this->id,
        /**
         * 订单号
         * @var string
         */
        'order_no' => $this->order_no,
        // ...
    ];
}
```

## 扩展包模式（--extension）

传入 `--extension=vendor/name`，所有代码生成到指定扩展包（`dcat-admin-extensions/<vendor>/<name>/`），命名空间、目录、路由全部按扩展包约定落位。

```bash
php artisan admin:scaffold \
  --table=orders \
  --api --admin-api --resource \
  --extension=acme/shop
```

### 命名空间与目录约定

以扩展根命名空间 `Acme\Shop` 为例：

| 产物 | 命名空间 | 文件位置 |
|------|----------|----------|
| Model | `Acme\Shop\Models` | `src/Models/Order.php` |
| 后台 Controller | `Acme\Shop\Http\Controllers` | `src/Http/Controllers/OrderController.php` |
| Resource | `Acme\Shop\Http\Resources` | `src/Http/Resources/OrderResource.php` |
| member-api | `Acme\Shop\Http\Api\Controllers` | `src/Http/Api/Controllers/OrderController.php` |
| admin-api | `Acme\Shop\Http\AdminApi\Controllers` | `src/Http/AdminApi/Controllers/OrderController.php` |

路由写入扩展包自己的路由文件：

```text
src/Http/routes.php           → Route::resource('order', OrderController::class)
src/Http/Api/routes.php       → Route::apiResource('order', ...) + 辅助端点
src/Http/AdminApi/routes.php  → Route::apiResource('order', ...) + 辅助端点
```

### 扩展包模式要点

1. **扩展包必须已存在**：先用 `admin:ext-make-pro` 创建骨架，再用本命令生成业务代码。
2. **根命名空间**优先读扩展包 `composer.json` 的 `psr-4`；缺失时按 `vendor/name` 推断（`acme/shop` → `Acme\Shop`）。
3. **member-api / admin-api 控制器继承的仍是主项目的 `BaseApiController`**（`App\Api\Controllers\...` / `App\Admin\Api\Controllers\...`），因为基类是项目全局的。
4. **路由用 `Route::` facade 风格 + 完整类名**追加到扩展包路由文件，与扩展包现有约定一致。
5. **菜单和权限仍写入主项目后台表**，生成后立即可在后台看到。若希望由扩展包自行注册菜单，可加 `--role=0`。

### 类名与表名前缀

命令按 `Str::singular(Str::studly($table))` 生成类名：

| 表名 | 生成的 Model 类 |
|------|-----------------|
| `orders` | `Order` |
| `order_items` | `OrderItem` |
| `shop_orders` | `ShopOrder` |

如果扩展包的表带统一前缀（见 [扩展包蓝图生成器](3-扩展包蓝图生成器.md) 的表名前缀约定），生成的类名会**带上前缀**（如 `shop_orders` → `ShopOrder` 而非 `Order`）。若希望得到纯类名 `Order`，有两个办法：

- 建表阶段就用无前缀的逻辑表名；
- 生成后手动重命名类（同时改 `$table` 属性）。

## 生成后必须人工补充

脚手架生成的是可靠起点，以下内容无法自动推断，需手工补：

```php
// 1. API 控制器的校验规则（默认空实现）
protected function getValidationRules(string $action): array
{
    return [
        'store' => [
            ['order_no' => ['required', 'string', 'max:64']],
            ['order_no.required' => '订单号不能为空'],
        ],
    ][$action] ?? [];
}

// 2. 后台表单的关联下拉、上传配置、富文本等
$form->select('user_id')->options(User::pluck('name', 'id'));
$form->image('cover')->disk('public')->dir('covers');
$form->editor('content');

// 3. Grid 调优：筛选器、列显示器
$grid->filter(function ($filter) { /* ... */ });
$grid->column('status')->using([0 => '禁用', 1 => '启用'])->label();
```

详细的人工补充项见 [智能脚手架](2-智能脚手架.md)「生成后的常见补充」。

## 常见场景速查

```bash
# 只生成后台 CRUD（最基础）
php artisan admin:scaffold --table=orders

# 重新生成（覆盖已有文件）
php artisan admin:scaffold --table=orders --force

# 主项目：后台 + 双端 API + Resource 一把梭
php artisan admin:scaffold --table=orders --api --admin-api --resource

# 扩展包：后台 CRUD
php artisan admin:scaffold --table=orders --extension=acme/shop

# 扩展包：全套（后台 + 双端 API + Resource）
php artisan admin:scaffold --table=orders --api --admin-api --resource --extension=acme/shop

# 扩展包：只生成接口层
php artisan admin:scaffold --table=orders --api --admin-api --extension=acme/shop
```

## 注意事项

1. `--api` / `--admin-api` 依赖主项目里的 `BaseApiController`，若项目未提供该基类，生成的控制器会报错。
2. API 控制器的 `getValidationRules()` 默认为空，生成后**务必补全**，否则 `store`/`update` 不做字段约束。
3. `--extension=` 模式只往 `src/` 写代码和路由，不创建扩展包骨架（用 `admin:ext-make-pro` 建包）。
4. `--force` 会覆盖 Model / Controller / Lang / Resource / API 控制器，使用前确认已有代码不需保留。
5. 扩展包模式的菜单/权限写入主项目后台表；若要让扩展包自管菜单，加 `--role=0` 并在扩展 `settingForm()` 或 `ext-install` 里配置。
