# 智能脚手架

智能脚手架在原有 CRUD 代码生成器的基础上，读取**字段名、数据库类型、字段注释**，为 `Grid`、`Form`、`Show` 自动生成更符合常见业务语义的字段代码。

访问地址：`/admin/helpers/scaffold`。

> 此功能仅在 `app.debug=true`、`admin.helpers.enable=true`，且当前用户是超级管理员时可用。

## 设计原则

- **保守优先**：只有证据充分时才生成专用组件；不能识别的字段仍生成普通文本字段。
- **可覆盖**：每个字段都有“语义类型”选择器；选择“普通文本”可关闭自动识别。
- **不猜业务关系**：`user_id`、`category_id` 等字段不会自动生成关联关系或下拉框。
- **不猜业务配置**：不会自动设置上传磁盘、上传目录、富文本编辑器、多图/多文件结构。
- **生成后仍需审查**：脚手架负责生成可靠的起点，关联、权限、复杂校验和业务展示规则须由开发者补充。

## 识别优先级

从高到低依次为：

1. 页面“语义类型”人工选择；
2. 字段注释中的 `@scaffold:type` 指令；
3. 字段注释中的 `@scaffold:options` 状态/枚举选项；
4. 数据库类型；
5. 高置信度的字段命名；
6. 普通文本字段回退。

## 命名、类型和生成结果

| 业务含义 | 推荐字段名/类型 | Grid | Form | Show |
| --- | --- | --- | --- | --- |
| 图片 | `banner_img`、`cover_image`、`avatar`、`logo`、`thumbnail` | `->image('', 44, 44)` | `->image()` | `->image()` |
| 文件 | `attachment_file`、`document`、`file` | `->downloadable()` | `->file()` | `->file()` |
| 邮箱 | `email` | 普通列 | `->email()` | 普通字段 |
| 手机/电话 | `mobile`、`phone`、`tel` | 普通列 | `->mobile()` | 普通字段 |
| 链接 | `url`、`website`、`homepage`、`link` | 普通列 | `->url()` | 普通字段 |
| 密码 | `password`、`passwd`、`pwd` | 不生成 | `->password()` | 不生成 |
| 颜色 | `color` | 普通列 | `->color()` | 普通字段 |
| 布尔值 | `boolean` 或 `tinyint(1)`；`is_enabled`、`is_visible`、`active` | `->bool()` | `->switch()` | `->bool()` |
| 日期 | `date` 类型 | 可排序列 | `->date()` | 普通字段 |
| 日期时间 | `datetime`、`timestamp`、`*_at` | 可排序列 | `->datetime()` | 普通字段 |
| 时间 | `time` 类型 | 可排序列 | `->time()` | 普通字段 |
| 整数/小数 | integer / decimal / numeric | 可排序列 | `->number()` / `->decimal()` | 普通字段 |
| JSON | `json`、`jsonb`；如 `metadata`、`settings` | `->limit(80)` | `textarea()->help('JSON')` | `->json()` |
| 长文本 | text / mediumText / longText；如 `content`、`description` | `->limit(80)` | `->textarea()` | 普通字段 |

`status` 或 `state` **本身不会**被自动解释为“启用/禁用”。只有明确配置选项时，才会生成 `select` 和 `using(...)->label()`。

## 使用字段注释指定语义

当字段名不符合约定，或者需要让以后“从已有表生成”仍保留语义时，在字段注释内增加指令。

```php
$table->string('banner_path')
    ->comment('首页 Banner 图 @scaffold:type=image');

$table->tinyInteger('publish_status')
    ->default(0)
    ->comment('发布状态 @scaffold:options={"0":"草稿","1":"已发布","2":"已下架"}');
```

支持的类型：

```text
auto, text, long_text, integer, decimal, image, file,
url, email, phone, password, color, status, boolean,
date, datetime, time, json
```

- `@scaffold:type=image`：强制按图片生成。
- `@scaffold:options={...}`：必须为 JSON 对象，自动作为状态/枚举下拉选项。
- 指令前的文字会保留为字段说明/标签。
- 无效 JSON、嵌套对象/数组、过多选项会被安全忽略，字段回退为普通行为。

### 正确与错误示例

```php
// 正确：结构化 JSON，能够稳定生成 select/options
->comment('审核状态 @scaffold:options={"0":"待审核","1":"通过","2":"拒绝"}')

// 正确：字段名模糊时明确指定图片
->comment('宣传素材 @scaffold:type=image')

// 不推荐：语义不完整，脚手架不会猜测数值代表什么
->comment('状态：0禁用 1启用')

// 不推荐：不要把 HTML、PHP、JavaScript、SQL 代码放入字段注释
->comment('<script>...</script>')
```

## 页面手工覆盖

Scaffold 页面中的“语义类型”默认是“自动识别”。适用于以下情况：

- 新建表还没有数据库 comment；
- 字段名受历史约束，不符合推荐命名；
- 同一项目某个字段需要临时不同的生成方式。

选择“状态/枚举”时，可在“枚举选项 (JSON)”填写：

```json
{"0":"草稿","1":"发布"}
```

页面覆盖只影响本次生成。需要持久化约定时，建议同步把 `@scaffold:` 指令写入 migration 的字段 comment。

## 生成后的常见补充

以下信息无法可靠从表结构推断，必须在生成控制器或模型中人工实现：

```php
// 关联：不要依赖 user_id 自动生成
$form->select('user_id')->options(User::query()->pluck('name', 'id'));

// 上传目录或磁盘
$form->image('banner_img')->disk('public')->dir('banners');

// 富文本需要显式选择并评估内容安全
$form->editor('content');

// 多图片需要模型 cast、存储格式以及显式字段定义
$form->multipleImage('gallery')->removable();
```

## 给 AI 建表的提示词

把下面提示词作为 AI 设计数据库表或 Laravel migration 时的约束：

```text
你正在为 Dcat Plus Admin 设计数据库表，请按“可安全自动生成后台 CRUD”的规则创建迁移和字段注释。

目标：
1. 字段名、数据库类型、字段注释应能帮助脚手架自动生成合适的 Grid、Form、Show。
2. 优先使用明确、稳定的命名；不要依赖模糊简称。
3. 除非模型关系和选项来源已明确实现，否则不要要求脚手架根据 *_id 自动生成关联下拉框或查询关系。

字段约定：
- 图片：avatar、cover、thumbnail、logo、banner、image、photo，或以 _img、_image 结尾；注释可写“头像”“封面图”“图片”。
- 文件：attachment、document、file，或以 _file 结尾；注释可写“附件”“文件”。
- URL：url、website、homepage、link。
- 邮箱：email。
- 手机/电话：mobile、phone、tel。
- 密码：password、passwd、pwd。
- 颜色：color。
- 布尔：is_enabled、is_visible、has_xxx、enabled、visible、active；数据库使用 boolean 或 tinyint(1)。
- 日期：使用 date；日期时间：使用 datetime/timestamp 或 *_at；时间：使用 time。
- 金额/小数：amount、price、rate，使用 decimal。
- JSON：metadata、settings、extra、payload，使用 json/jsonb。
- 长文本：content、description、remark、body，使用 text/mediumText/longText。

状态和枚举：
- 有固定选项的状态字段，必须写明确的脚手架选项注释：
  @scaffold:options={"0":"草稿","1":"已发布"}
- 需要强制指定控件时，使用：
  @scaffold:type=image
  @scaffold:type=boolean
  @scaffold:type=color
- 字段业务说明写在指令前，例如：
  发布状态 @scaffold:options={"0":"草稿","1":"已发布"}
  封面图 @scaffold:type=image
- 不要只写“0禁用1启用”“状态”等非结构化描述；脚手架不会猜测枚举含义。

安全与兼容性：
- 不要在字段名、注释、枚举标签中放入 PHP、HTML、JavaScript 或 SQL 片段。
- 不要要求自动生成富文本输出、上传目录、关联模型、外键下拉框；这些需要在生成后的控制器中显式配置。
- 请输出 Laravel migration 字段、中文 comment、nullable/default/index/unique 设计，并逐字段说明用途。
```
