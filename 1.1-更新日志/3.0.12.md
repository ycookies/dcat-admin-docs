## 主要新增

### 1. 扩展包本地安装预检：全部错误一次性返回
- 后台上传 zip 安装扩展时，此前无论失败原因是什么都只报一句 `Unable to extract core file '...'`，用户无法区分是 **Zip 扩展缺失、压缩包损坏、目录权限、磁盘空间** 中的哪一个，只能逐个失败逐个排查；
- 现在解压前会**一次性跑完全部环境检查，把所有问题同时返回**：

| 检查项 | 覆盖的失败场景 |
|---|---|
| PHP Zip 扩展 | `ext-zip` 未安装/未启用（附宝塔面板修复指引） |
| 压缩包文件 | 不存在/已过期、不可读、0 字节（上传中断）、非 zip（ER_NOZIP）、损坏（ER_CRC/ER_INCONS）、空包 |
| 临时目录 | `storage/tmp/extensions` 不可写/无法创建（提示 755 + 属主改 PHP 运行用户） |
| 扩展安装目录 | `dcat-admin-extensions/` 不可写/无法创建 |
| 磁盘空间 | 按 zip 体积 5 倍估算需求对照 `disk_free_space`（函数被禁用时安全跳过） |

- 错误消息全部为**可读中文 + 带具体路径和修复指引**，例如：
  > 临时目录不可写：/www/xxx/storage/tmp/extensions。请将目录权限设为 755（或 775）并将属主改为 PHP 运行用户后重试。
- 预检能力可独立复用（自定义安装流程）：

```php
use Dcat\Admin\Extend\InstallPreflight;

$errors = (new InstallPreflight())->check($zipPath);
// 空数组 = 环境全部通过；非空 = 全部问题的消息列表
```

## 修复

### 2. Zip::extract 忽略解压失败的问题
- 此前 `extractTo()` 的返回值被忽略——**磁盘满、目录无写权限导致解压写入失败时依然返回成功**，错误被拖到后续"Error extension file"这种更难懂的位置；
- 新增第 4 个引用参数回填失败的具体原因，`Manager` 的异常消息也会附带：

```php
$error = null;
Zip::extract($src, $dest, [], $error);   // 失败时 $error = '解压写入失败（...）：请检查磁盘剩余空间与目录写权限。'
```
