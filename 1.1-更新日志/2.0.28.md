## 主要新增

### 1. Markdown 编辑器支持粘贴图片自动上传
- 在 Markdown 编辑器内直接 **Ctrl+V / Cmd+V 粘贴截图**，图片自动上传并在光标处插入 `![](url)` 语法，无需再走"存文件 → 传图床 → 复制链接 → 手写语法"的流程：

```markdown
粘贴后自动插入：
![](https://your-domain.com/storage/markdown/images/67c04674e5afe.png)
```

- 特性细节：
  - 走编辑器原有 `imageUploadURL` 上传通道，`disk()` / `imageDirectory()` 存储配置、文件类型白名单校验照常生效，**无需任何额外配置，开箱即用**；
  - 一次粘贴多张图片时逐张上传、逐张插入，上传过程有 toast 提示，失败提示错误信息；
  - 纯文本粘贴不受影响；只读字段不启用。

```php
// 上传目录与存储盘配置方式不变
$form->markdown('content')->disk('oss')->imageDirectory('posts/images');
```

### 2. Markdown 编辑器全屏按钮悬浮到右上角
- "全屏（按ESC还原）"按钮原本埋在 40 多个工具按钮中间，现在**自动悬浮在编辑器右上角**：
  - 一眼可见、一点即进全屏；
  - 全屏状态下按钮继续悬在右上角，**再点即退出**（ESC 依然有效）；
  - 工具栏预留右侧空间，不遮挡原有工具按钮；适配深色模式。

### 3. $form->table() / array() 字段达到 useTable 同款表格体验
- 修复 `table` / `array` 字段（JSON 存储）共用表格视图但丢失样式钩子的问题：表头列空白、行内字段带 label、help 挤在单元格内。现在与 `hasMany()->useTable()` **完全一致**，同一段字段定义可原样互搬：

```php
// JSON 单列存储（无需建关联表），体验与 hasMany useTable 完全一致
$form->table('items', '报名项目', function (NestedForm $table) {
    $table->select('type', '类型')->options(RegistrationItem::typeOptions());
    $table->text('name', '项目名称')->required();
    $table->decimal('price', '单价(元)')
        ->columnWidth('120px')
        ->help('个人=每人价（¥260/人）；团体=每队价（¥3280/队）');
    $table->number('quota', '名额(0不限)')->default(0);
    $table->switch('is_enabled', '启用')->default(1);
});
```

- 结构化表头、`columnWidth()` 列宽、help 上收表头（❓ 图标 + 气泡）、switch/number 居中收窄等能力全部生效；
- 存量 table 字段（升级前已存在的）表头空白问题同步修复。

## 修复

### 4. 嵌套表格新增行的 select 无下拉箭头
- **现象**：hasMany/table 表格点「新增」，新增行的下拉框没有向下箭头，看起来像普通输入框。
- **根因**：AdminLTE 主题给 `select.form-control` 设置了 `appearance: none`（预期由 select2 渲染箭头），而框架的组件初始化机制（`Dcat.init`）不监听动态插入的 DOM——新增行克隆模板后，select 永远等不到 select2 挂载。
- **修复**：新增行追加后自动挂载 select2（与数据行渲染一致）；同时给原生 select 恢复原生箭头兜底，任何情况下下拉框都"长得像下拉框"。`hasMany()` 默认模式与 `->useTable()` 表格模式一并修复。

> **二次开发提示**：自定义嵌套行内组件时，必须在「新增」回调中手动初始化组件，不能依赖 `Dcat.init` 自动重放（详见 `.claude/skills/references/infrastructure.md` 前端集成要点）。
