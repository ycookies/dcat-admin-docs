## 修复

### 1. 内置 zgldh/qiniu-laravel-storage 的 Flysystem v3 兼容补丁

**背景**：宿主项目安装 `zgldh/qiniu-laravel-storage` 后，后台媒体管理器（`dcat-sys/media`）浏览七牛盘直接 500。

**根因**：锅在第三方包 zgldh——它的 `QiniuAdapter::listContents()` 返回的还是 Flysystem **v1 风格关联数组**，而 Laravel 10+ 的 `files()` / `directories()` 内部对 `StorageAttributes` 有强类型过滤，必然 TypeError。dcat-plus 调用 `Storage::disk()->files()` 是标准姿势，换任何本地/S3 盘都不会炸——只是媒体管理器恰好是这个 bug 最容易暴露的入口。由于 dcat-plus 分发出去，下个项目只要装了 zgldh 就会再踩，因此把兼容补丁内置进包。

**实现**（未安装 zgldh 的项目 `class_exists` 守卫，零开销）：

- 新增 `Support\QiniuV3Adapter`（zgldh 适配器子类）：
  - `listContents()` 返回 Flysystem v3 要求的 `StorageAttributes` 对象；
  - **marker 分页拉全**（原实现只取前 1000 条）；
  - 浅层列表带 `delimiter='/'`，用 `commonPrefixes` 还原子目录（媒体库文件夹导航）；
  - `putTime`（100 纳秒单位）÷1e7 转秒级时间戳；
  - 构造时域名前缀统一 **https**（原适配器硬编码 `http://`，`getUrl()` 拼出的 URL 也是 http）；
- `AdminServiceProvider::patchQiniuStorageDriver()`：注册放进 **`App::booted` 回调**——zgldh 在它自己 provider 的 boot 阶段注册 `Storage::extend('qiniu')`，provider boot 顺序不保证谁后；而 booted 回调必然在所有 provider boot 之后执行，同名覆盖必胜。

```php
// 宿主要完全自定义 qiniu 驱动：在自己的 App::booted 里再 extend 一次即可（后注册者胜）
\App::booted(function () {
    \Illuminate\Support\Facades\Storage::extend('qiniu', function ($app, $config) {
        return ...;  // 你的适配器
    });
});
```

**实测**：适配器覆盖生效、`files()/directories()` 正常返回、URL 全 https、媒体管理器 `ls('video')` 正常。

### 2. 嵌套弹窗补丁升级完整版

在 v3.0.14 五死因根治的基础上追加：

- **内层提交智能局部刷新**：弹窗内表单提交成功后不再整页 reload——拦截 `Dcat.reload`，通过 `data-nested-from` 记录的来源外层 id，只精准重载来源外层弹窗（框架化，所有嵌套弹窗表单受益）；
- `pjax:complete` 时清理移出到 body 的嵌套内层残留（页面级 modal 随容器替换等效关闭，移出的内层不在 pjax 容器内会残留）。
